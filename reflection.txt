A stack is the right choice for an undo/redo system because it follows the Last In, First Out (LIFO) principle. This means the most recent action is the first one removed. When a user performs an action, it is added to the undo stack. When the user selects undo, that action is removed from the undo stack and added to the redo stack. If the user selects redo, the action moves back to the undo stack. My implementation uses two stacks to manage these actions. It also clears the redo stack when a new action is performed because the previous redo history is no longer valid.

A queue is better suited for a help desk because it follows the First In, First Out (FIFO) principle. This means the first customer to enter the queue is the first customer helped. This system is fair because customers are helped in the order they arrive. My Queue class uses enqueue to add customers to the rear and dequeue to remove customers from the front. It also includes methods to view the next customer and print everyone waiting.

My implementations differ from Python's built-in lists because they use linked nodes instead of storing items in a dynamic array. Each node holds a value and a reference to the next node. The stack uses a top reference, while the queue uses front and rear references. These implementations demonstrate how stacks and queues work internally. They also allow specific operations to be performed without relying on built-in list methods such as append and pop.
